# Установка Cerastilo

Планировщик встреч «Жизнь и служение» на Python 3 + PySide6. Один интерфейс на компьютере (Linux и Windows) и в APK для Android-планшетов (arm64).

## Установка релизных пакетов

* **AUR (Arch Linux).** Выполните `yay -S cerastilo`.
* **AppImage (Linux).** Выполните `chmod +x Cerastilo-*.AppImage` и запустите файл двойным щелчком. Данные по умолчанию хранятся в `~/.local/share/cerastilo`.
* **Windows.** Распакуйте ZIP и запускайте `cerastilo.exe`; остальные файлы в этой папке не трогайте и не удаляйте. Данные хранятся в `%LOCALAPPDATA%\Cerastilo`.

## 1. Компьютер на Linux

### Требования

* Linux с рабочим столом (программа — графическое приложение на Qt 6).
* Python 3 (версия, под которую собран PySide6 6.12 в `requirements.txt`).
* Интернет — только на первом шаге, чтобы скачать зависимости.

### Установка зависимостей

Зависимости ставятся в локальное виртуальное окружение `.venv` в папке проекта:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

`requirements.txt` фиксирует версию PySide6 (6.12.0 — та же, что в Android-сборке), а также SQLAlchemy 2.x, Alembic, BeautifulSoup, lxml, python-docx и другие библиотеки.

### Запуск

```bash
./start.sh
```

`start.sh` меняет рабочий каталог на папку программы и запускает `main.py` из `.venv`. Без скрипта — так же: `.venv/bin/python main.py`.

### Где лежит база

Данные программы (возвещатели, расписание, настройки, история уведомлений) хранятся в локальной базе **`scheduler.db` в папке программы**. Перед первым запуском базы может не быть — программа создаст её при старте; существующую базу при этом не трогает.

### Первый запуск

1. Запустите `./start.sh`.
2. Программа применит сохранённую тему (или системную, если выбрано «Как в системе») и выполнит служебные обновления структуры данных (миграции), чтобы база соответствовала текущей версии.
3. Откройте вкладку **«⚙️ Настройки»** и заполните блок **«Настройки собрания»**: название собрания, день и время встречи, интервалы отдыха.
4. Загрузите программу встреч: вкладка **«📚 Тетради»** — импорт рабочей тетради из EPUB (подробно — глава 4 руководства).
5. Добавьте возвещателей: вкладка **«👥 Возвещатели»** → **«➕ Добавить»** (глава 5).

Если при запуске что-то пойдёт не так, программа покажет окно **«Ошибка запуска»**; при ошибках во время работы — окно с сообщением. Журнал сбоев `crash.log` пишется в папку программы (на компьютере) — его можно передать разработчику.

### Тесты

Для запуска тестов нужны зависимости разработчика (`requirements-dev.txt` — pytest, pytest-qt и др.). Из корня проекта:

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest --no-cov tests/
```

`QT_QPA_PLATFORM=offscreen` — headless-режим, чтобы тесты не открывали реальные окна.

## 2. Сборка APK для Android-планшетов (arm64)

### Что нужно

* Окружение сборки с Python 3.14 и PySide6 6.12 (`.android-venv` в папке проекта).
* Колёса (wheels) PySide6 и Shiboken6 для Android arm64 — в `~/Android/wheels`.
* Android SDK и NDK r28c — в `~/Android/Sdk`.
* JDK 17 — в `~/Android/jdk-17` (Gradle не работает с более новой Java).

Пути заданы в начале `android/build_apk.sh`; если у вас другие, поправьте их там.
* Пакеты сборки `python-for-android` и `pyside6-android-deploy` в `.android-venv`.

### Сборка

```bash
bash android/build_apk.sh aarch64
```

Скрипт собирает код приложения в `android/build_src/` (не в git): копирует `core/`, `ui/`, `modules/`, `assets/`, `migrations/`, десктопный `main.py` — как `app_main.py`, `android/main.py` — как точку входа. Готовый APK кладётся в `android/`.

**Собирается только arm64** — и для планшета, и для Waydroid (там arm64 идёт через трансляцию). x86_64 не собирается.

**Время сборки.** Полная сборка с нуля — около 40 минут (компилируется Python под Android). С сохранённым кэшем — около 2 минут. Любое изменение списка зависимостей (`APP_REQUIREMENTS`) сбрасывает кэш python-for-android — снова ~40 минут.

**Только подготовить код без сборки:**

```bash
STAGE_ONLY=1 bash android/build_apk.sh
```

### DOCX, S-89 и импорт EPUB в APK

По умолчанию в APK не входят python-docx и lxml. Чтобы включить экспорт в Word, бланки S-89 и импорт рабочих тетрадей (EPUB), соберите APK с флагом `WITH_DOCX=1`:

```bash
WITH_DOCX=1 bash android/build_apk.sh aarch64
```

При этом добавляются python-docx, beautifulsoup4, soupsieve, six и lxml (для lxml и libxml2 подключены собственные рецепты python-for-android). Изменение списка требований сбрасывает кэш — сборка снова займёт около 40 минут.

### Установка на планшет

```bash
adb install -r android/Cerastilo-0.1-arm64-v8a-debug.apk
```

Запуск и просмотр журнала (на планшете или в Waydroid):

```bash
adb logcat -c && adb shell am start -n org.cerastilo.cerastilo/org.kivy.android.PythonActivity
adb logcat -d | grep -E " python " | grep -v extracting
adb exec-out screencap -p > screen.png
```

Финальная проверка — на настоящем планшете.

### Где данные на планшете

Рабочая база на планшете живёт **в постоянной папке данных** (`ANDROID_PRIVATE`), отдельной от кода приложения, — обновление APK не стирает расписание. В сам APK рабочая база не кладётся (в ней личные данные): планшет стартует с пустой базой, данные приходят синхронизацией с ПК (см. ниже).

## 3. Перенос данных ПК ↔ планшет

**Синхронизация ПК и планшета по Wi-Fi идёт без шифрования. Используйте её только в доверенной домашней сети.**

1. На компьютере откройте вкладку **«⚙️ Настройки»**, блок **«🔄 Синхронизация ПК ↔ планшет»**, нажмите **«🔄 Синхронизация с планшетом»**. Откроется окно с **Адресом** (например, `192.168.1.5:8765`) и **Кодом** из 6 символов.
2. На планшете откройте **«⚙️ Настройки»**, блок **«🔄 Синхронизация ПК ↔ планшет»**, нажмите **«🔄 Синхронизировать с ПК»** и введите адрес и код из окна на компьютере.
3. Компьютер объединит свою базу с планшетной и вернёт объединённую; планшетная версия закроется — откройте её заново.

Порт по умолчанию — **8765**, но при запуске сервер выбирает свободный порт, и в окне показывается актуальный адрес с портом. После 5 неверных попыток ввода кода сервер блокируется. На компьютере порт должен быть открыт в брандмауэре (например, `sudo ufw allow 8765/tcp`).

Подробно — глава 11.5 руководства: [`docs/help/ru/guide.md`](help/ru/guide.md).
