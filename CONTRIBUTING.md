# Руководство для участников разработки (Contributing)

Спасибо за интерес к проекту **Cerastilo** — планировщику встреч «Жизнь и служение» на Python 3 + PySide6 (Qt 6), с SQLite через SQLAlchemy + Alembic. Один интерфейс работает на ПК (Linux) и в APK для Android-планшетов (arm64).

## Как сообщить об ошибке

Опишите проблему так, чтобы её можно было воспроизвести:

* **что делали** — какая вкладка, кнопка, действие (например, «📅 Расписание → 🪄 Авто-распределение месяца»);
* **что ожидали** и **что произошло на самом деле**;
* **платформа** — компьютер (Linux) или Android-планшет;
* при необходимости — **журнал сбоев** `crash.log`: на компьютере он пишется в папку программы, на планшете — в папку данных приложения.

Перед отправкой полезно проверить **«⚙️ Настройки»** (например, параметры собрания, интервалы, SMTP) и убедиться, что база не повреждена.

## Как поднять окружение

Нужны Python 3 и Linux с рабочим столом (программа — графическое приложение на Qt 6).

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt          # runtime-зависимости
.venv/bin/pip install -r requirements-dev.txt      # тесты и линтеры
./start.sh                                          # запуск приложения
```

`start.sh` меняет рабочий каталог на папку проекта и запускает `main.py` из `.venv`.

Зависимости разработчика (из `requirements-dev.txt`): pytest, pytest-cov, pytest-qt, hypothesis; black, isort, flake8 (+ flake8-docstrings, flake8-bugbear), mypy, pre-commit; pdoc, sphinx, sphinx-rtd-theme.

## Структура кода

| Каталог / файл | Назначение |
|---|---|
| `main.py` | Точка входа десктопа; `start.sh` запускает его из `.venv` |
| `core/` | Бизнес-логика, работа с БД (SQLAlchemy + Alembic), экспорт, импорт, уведомления, синхронизация |
| `ui/` | Виджеты и диалоги Qt (вкладки, карточки участников, диалоги писем и журнала уведомлений) |
| `android/main.py` | Точка входа APK: готовит папку данных (`ANDROID_PRIVATE`), включает прокрутку пальцем и запускает то же главное окно (`app_main.py` — копия `main.py`) |
| `android/build_apk.sh` | Сборка APK; код складывается в `android/build_src/` (не в git) |
| `migrations/` | Миграции Alembic |
| `tests/` | Тесты (pytest, pytest-qt в headless-режиме) |

В `core/` есть отдельные файлы, на которые стоит обращать внимание:

* `android_migrations.py` — чисто-питоновские миграции для Android; базу с версией Alembic 012+ (поставленную десктопом) они не трогают;
* `utils/android_storage.py`, `ui/file_dialogs.py` — на Android файлы экспорта и бэкапа пишутся в «Загрузки/Cerastilo» без системного диалога (диалог Qt на Android возвращает `content://`, который нельзя открыть обычным `open()`).

## Правила

### Тесты должны проходить

Перед коммитом и перед PR прогоните тесты в headless-режиме (чтобы они не открывали реальные окна):

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest --no-cov tests/
```

Настройки pytest (в `pyproject.toml`) включают покрытие по умолчанию; флаг `--no-cov` его отключает для быстрого прогона. Если нужен отчёт по покрытию — запускайте без `--no-cov`: `pytest --cov=core --cov=ui`.

### Миграции

Схема базы меняется через **Alembic**: новая миграция — в `migrations/`. Для Android те же изменения повторяются чисто на Python в `core/android_migrations.py`. Если схема меняется, проверьте, что обновлены оба места (Alembic и Android-миграции).

### Признак Android в коде

Проверка платформы — `core.utils.android_storage.is_android()`, которая смотрит на наличие переменной окружения `ANDROID_ARGUMENT`. Если нужно разное поведение на ПК и планшете (диалоги сохранения файлов, отключение модулей, которых нет на Android), ориентируйтесь на эту функцию.

### Не коммитить рабочую базу

`scheduler.db` в корне проекта — рабочая база с личными данными; её **не коммитят** и не портят. Копию для экспериментов называйте не `scheduler.db` — `migrations/env.py` подменяет URL `sqlite:///scheduler.db` на рабочую базу, а `DatabaseManager` прогоняет миграции при каждом создании. Экспериментируйте с базой только на отдельной копии.

## Стиль коммитов и комментариев

* Коммиты — по-русски, в формате Conventional Commits: `feat(android): …`, `fix: …`, `docs: …`.
* Комментарии в коде — по-русски.

## Как отправить PR

1. Сделайте ветку от актуального состояния репозитория.
2. Внесите изменения небольшими коммитами по одной теме.
3. Прогоните тесты (см. выше), убедитесь, что они проходят.
4. Откройте pull request с кратким описанием: что изменилось, зачем, какие вкладки/функции затронуты, какие тесты добавлены.
5. Если меняются схема БД, сборка Android или миграции — упомяните это отдельно и проверьте, что обновлены и Alembic, и `core/android_migrations.py`.

Спасибо за вклад в развитие Cerastilo!
